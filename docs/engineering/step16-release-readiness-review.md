# Step 16 — Security and infrastructure release readiness

Reviewed 26 October 2026 against commit `08a963e` on `feature/money-payment-reconciliation`. This is a repository review plus `pnpm audit --prod --audit-level high`, not a production certification. **Release gate: open.** The production SMS and web paths have confirmed configuration blockers; backup recovery and real-device behavior lack verification.

## Confirmed blockers

| Priority | Finding and evidence | Pass condition |
| --- | --- | --- |
| P0 | **Production OTP cannot start through the default app wiring.** `apps/api/src/modules/identity/identity.container.ts` requires an injected non-console SMS gateway in production, but the default container supplies `ConsoleSmsGatewayAdapter`; no provider adapter is wired. The fail-closed guard is correct, but `createApp()` will throw. | Implement and inject a real SMS provider; boot the API and request/verify OTP in production-like staging with `STAGING_UNSAFE` off. Verify delivery failures, retry/cooldown, rate limits, and that fixed OTP cannot be enabled in production. |
| P0 | **Web production image and API URL are misconfigured.** `apps/web/Dockerfile` builds `@Cabzonee/web`, while `apps/web/package.json` names `@cabzone/web`. `apps/web/src/lib/api/client.ts` reads a build-time `NEXT_PUBLIC_API_BASE_URL`, but `docker-compose.prod.yml` supplies `http://api:4000/api` only at runtime. The Docker-only hostname is unsuitable for a browser. | Correct the package filter; build the image; supply a browser-reachable HTTPS API origin at build time or use a same-origin proxy. Smoke-test a browser session against the built image. |
| P0 | **Production dependencies have unresolved advisories.** `pnpm audit --prod --audit-level high` reported 15 advisories: 1 critical, 8 high, 6 moderate. Critical: `next` image optimization SVG RCE. High: `next`, `postcss` (two), `node-forge`, `source-map-js`, `sharp`, `zod`, `body-parser`. Reachability has not been established. `.github/workflows/ci.yml` has no audit gate. | Triage each advisory against actual runtime inputs; upgrade or document a tested mitigation, then make the chosen audit threshold pass in CI. Test the web image and API after upgrades. |
| P0 | **Recovery from datastore loss is unproven.** `docker-compose.prod.yml` uses one Mongo replica-set member and one Redis instance with local named volumes. No off-host backup schedule, retention, restore procedure, or restore drill was found in the repo. Redis AOF is local persistence, not a backup. | Define RPO/RTO; run encrypted off-host Mongo backups and a Redis recovery plan; restore into a clean environment and reconcile ride, payment, wallet, and queue records. Record restore time and data loss. |

## Existing safeguards worth retaining

Production rejects fixed OTP (`apps/api/src/config/env.ts`); OTP attempts and cooldowns are stored in shared Mongo and rate-limited; identity boot fails closed without a real provider. Mongo and Redis expose health checks, and API shutdown drains resources. Mobile contexts restore active state on foreground. These controls need end-to-end proof in production-like builds.
