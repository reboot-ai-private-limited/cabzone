## 2. Agent ownership and working agreement

**Agent A — highest reasoning load: backend correctness and integration.** Assign the most capable agent here. A owns concurrent booking and payment rules, wallet/ledger reconciliation, pricing and immutable ride snapshots, extension state transitions, ratings privacy, `packages/contracts`, API ride/pricing/ledger modules, database migrations, and the sole integration branch. These tasks carry the greatest risk of duplicate charges, lost earnings, or inconsistent ride state. A reviews and integrates the already committed feature branches; a pushed branch is not a verified release.

**Agent B — product interfaces.** Own rider and driver app screens, `apps/web` UI, client state/navigation, accessibility, and low-end Android interaction/performance. Reuse the existing white backgrounds, brand colors, inputs, navigation, and component patterns. B starts dependent UI only after A publishes the corresponding API/event contract.

**Agent C — platform and release systems.** Own SMS and KYC adapters, push transport/native configuration, dependency and image builds, CI, backup/restore, monitoring, deployment checks, device background/restart qualification, and specialist evidence collection. C hands API bootstrap changes to A and client deep-link changes to B.

| Shared surface                                                           | Single writer and handoff                                                                                                                       |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/contracts/**`, API ride/pricing/ledger controllers and Swagger | A commits contracts first; B and C consume them and request additions through A.                                                                |
| `apps/api/src/container.ts`, `routes.ts`, `server.ts`, `worker.ts`       | A wires C's committed identity/push/monitoring modules from an exact checklist.                                                                 |
| Identity/push public interfaces                                          | C owns the module interfaces; A reviews cross-module/API effects before integration.                                                            |
| `apps/web/**`, rider/driver screens and client contexts                  | B owns UI and state. C owns `apps/web/Dockerfile`, mobile native build/configuration, and provider credentials; coordinate edits to app config. |
| Root/app manifests, `pnpm-lock.yaml`, CI                                 | C owns dependency changes. Freeze lockfile writes during upgrades; A and B hand over manifest needs.                                            |
| Migrations, indexes, staging database                                    | A executes reviewed changes serially. C verifies backup/restore before any apply.                                                               |
| `graphify-out/**`                                                        | A generates one consolidated update after each integrated code checkpoint.                                                                      |
| `tasks/todo.md`, shared work order and workbook                          | A maintains statuses; B supplies UI/device evidence; C supplies provider/operations evidence. Synchronize once per checkpoint.                  |

Use separate worktrees and short feature branches from the last integrated SHA. Check existing worktree ownership before editing. Never stash, reset, delete, or commit another agent's unreviewed work to make room. Each verified logical change gets a local commit; push only when requested. Integrate one reviewed feature at a time with focused checks. Record task ID, base/feature SHA, owned files, API/event changes, tests, and risks in the checklist. Device/provider evidence must identify build, device/OS, environment, and timestamp without secrets or personal data.
