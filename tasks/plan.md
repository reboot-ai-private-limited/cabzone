## 2. Agent ownership and working agreement

**Agent A: backend policy, money correctness, contracts, and integration.** Own `apps/api/src/modules/rides`, `pricing`, `ledger`, related repositories/migrations/tests, and `packages/contracts`. Act as the sole integrator for the shared release branch. Resume existing booking, arrears, ratings, and money work with its original owner before changing it.

**Agent B: rider/driver/web delivery, identity/push hardening, and release infrastructure.** Own both mobile apps, `apps/web`, identity SMS/KYC and dispatch push internals, build/deploy/backup/monitoring configuration, native credentials setup, device acceptance, and documentation collection. Reuse the existing white backgrounds, brand colors, inputs, navigation, and component patterns.

| Shared surface                                                           | Single-writer rule                                                                                                                             |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/contracts/**`, API ride/pricing/ledger controllers and Swagger | A changes and commits the contract first. B consumes the committed contract and requests additions through a handoff.                          |
| `apps/api/src/container.ts`, `routes.ts`, `server.ts`, `worker.ts`       | A owns integration edits. B supplies its committed adapter/module changes and an exact wiring checklist; A wires them.                         |
| Identity/push public interfaces and dependency direction                 | B proposes required changes; A reviews cross-module effects before the API contract is frozen. Do not bypass the project's module boundaries.  |
| Root/app manifests, `pnpm-lock.yaml`, CI                                 | B owns dependency changes. Freeze lockfile writes while B upgrades packages; A hands over any manifest needs first.                            |
| Migrations, indexes, staging database                                    | A executes reviewed database changes serially. B takes/verifies the backup and records restore evidence before any apply.                      |
| `graphify-out/**`                                                        | A generates one consolidated update after each integrated code checkpoint. Never merge competing generated graphs as source code.              |
| `tasks/todo.md`, shared work order and workbook                          | A maintains checklist/commits/blocked items. B provides device/operations evidence. Final tracker synchronization happens once per checkpoint. |

Use separate worktrees and short feature branches based on the last integrated SHA. No simultaneous edits in one checkout. Before claiming a file, check other worktree status; if an existing owner is using it, receive a commit/handoff first. Never stash, reset, delete, or commit another owner's unreviewed work to make room.

Each verified logical change gets a local commit. Push only when the user explicitly requests it. Integrate one reviewed feature at a time, run its focused checks, then move to the next. Do not repeatedly replay a branch already contained in the baseline. For a shared-file handoff record task ID, base/feature SHA, owned files, API/event changes, tests run, and remaining risks in the task checklist. Native or provider evidence must also identify the installed build, device/OS, environment, and timestamp without secrets or personal data.
